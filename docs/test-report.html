Logic Validation - What Was Tested

1. Add Entry - Dashboard Updates

Insert via Repository, Flow emits new list, calculateDashboardStats() recomputes latestOdometer, totalCost, totalFuel. With 1 entry: avgMileage/costPerKm remain null. With 2+: all stats computed correctly.

2. Add Entry - Charts Update

Insert via Repository, calculatePerFillupMileage() adds fillup point (first = null mileage, subsequent = distance/liters). calculateMonthlySpend() groups by calendar month and sums cost/liters.

3. Edit Entry - All Recalculate

Update entry via Repository, Flow emits same-count list, dashboard + charts recalculate with new values. Edit odometer/liters/cost, mileage per fillup, totals, averages all shift correctly.

4. Delete Entry - All Recalculate

Delete via Repository, list shrinks, dashboard recalculates with remaining entries. Delete last entry, all stats reset to null/0. Delete middle, adjacent entries recompute mileage gap correctly.

5. Flow Auto-Propagation

repository.getAllEntriesFlow() returns Room Flow<List<FuelEntry>>. Any insert/update/delete triggers emission, ViewModel map {}, stateIn(), Compose collectAsState() recomposition. No manual refresh needed.

6. Odometer Monotonicity

FuelEntryValidator rejects new entries where odometer less than or equal to previous max. Enforces strictly increasing sequence. Edit mode skips this check (allows re-saving current odometer).

7. Edge: Same Odometer

Two entries with identical odometer, totalDistance = 0, avgMileage = null, costPerKm = null. Per-fillup mileage for 2nd entry = 0.0. No division-by-zero.

8. Edge: Single Entry Lifecycle

Add 1, Dashboard shows odometer + totals, no avg/costPerKm. Add 2nd, stats appear. Delete back to 1, stats vanish. Delete to 0, empty state. Full round-trip verified.

9. Monthly Spend Grouping

Entries across different months grouped by (year, month) via Calendar. Chronologically sorted. Skipped months not represented. Cost and liters summed per group. Verified with Jan/Feb/Apr test.

10. DB Persistence (Force-Close)

entriesPersistAcrossDatabaseReopen: insert, close DB, reopen, entry still present. Confirms Room writes are atomic and survive process termination (PRD FR15/FR16).

11. Performance: 5000 Entries

Bulk insert 5000 entries + getAll() + 20x getLatest() + 50x getById() all complete well under thresholds. Indexed queries (date, odometer, composite) verified efficient.

12. Validation: All Reject Paths

Empty fields, required errors. Negative/zero, positive errors. Odometer less than or equal to previous, monotonic error. Null date, date error. All 4 validation rules independently tested.
